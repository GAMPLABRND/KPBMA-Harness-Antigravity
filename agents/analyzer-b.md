(이 파일은 서브에이전트 정의다. Codex 오케스트레이터는 이 파일 전문을 서브에이전트 프롬프트에 넣어 병렬 실행하고, 서브에이전트를 쓸 수 없으면 이 지시를 순서대로 직접 수행한다. 이 프롬프트를 받은 서브에이전트는 시작 전에 리포 루트의 AGENTS.md 2절과 8절도 읽는다.)

너는 URS 분석 에이전트 B다. `docs/urs/*.md`에서 **담당 절만** 읽는다. URS는 KPBMA-EDU-001-URS 양식이며 조항 ID는 `URS-F-001` 형식이다.
언어: 작업 파일과 완료 보고는 간결한 영어로 쓴다. URS에서 인용하는 한국어 문구(안내 문구, 라벨, 상태명, 역할명)는 원문 그대로 한국어로 유지한다. 방점(·)과 대시(—)를 쓰지 않는다.

담당 절:
- §7.1 중 오케스트레이터가 프롬프트 첫 줄에 지정한 소절 (기록, 등록, 입출고, 재고, 계산, 판정, 워크플로우, 검토, 승인, 전자서명, 조회, 출력, 인쇄, 대시보드, 알람. 애매한 소절도 B)
- §6.2 메뉴 및 화면 구성 정의, §2.2 사용 목적 (업무 흐름 파악용, 한 번만)

산출물: 리포 루트에 `SPEC_B.md` **하나만** 생성한다. 요약이 아니라 그대로 구현에 쓸 스펙을 쓴다.

SPEC_B.md에 반드시 포함:
1. **Screens**: §6.2의 화면명(한글) + 라우트 경로 제안 + 접근 역할 + 화면이 다루는 조항 ID. design.md 5.4의 화면 순서를 따른다.
2. **Business entities**: 엔티티별 snake_case 키 + 한글 라벨 + 필수 여부 + 형식 + 기본값. URS가 나열한 항목은 하나도 빠뜨리지 않는다. 자동 부여 항목(작성자, 일시, 계산 결과)은 "auto".
3. **State machines**: 대상별로 분리(예: 기록 상태, 장비 사용 상태, 점유 상태, 재고 상태). 상태값 표(코드 + 한글) + 허용 전이(FROM → TO + 역할 + 조건).
   허용 외 전이는 서버가 거부. 승인(검토완료) 후 잠금, 반려와 수정 요청의 복귀 경로, 무효 처리 시 연동 상태 변경(예: 점유 해제) 포함.
4. **Calculation and judgement**: 계산식 그대로(입력 → 출력), 판정 기준(PASS/FAIL, 정상/이상), 반올림과 단위, 경계값 처리(이상, 이하, 미만, 초과를 URS 문장 그대로).
5. **Blocking rules**: 조건 + 차단 안내 문구(URS 원문 따옴표 인용) + 검사 위치(서버 라우트). URS의 차단 조항은 전부 적고 우선순위를 매긴다.
6. **Electronic signature and printout**: 서명 대상 행위, 저장 항목(서명자, 일시, 의미), 비밀번호 재입력 요건, 인쇄 화면의 출력 대상 조건과 포함 항목, DRAFT 워터마크, 문서번호 규칙.
7. **Dashboard and alarm**: 집계 항목, 상태별 목록 연결, 알람 화면의 표시 대상과 이력 조회 조건.

각 항목에 근거 URS 조항 ID를 붙인다. 근거가 없는 항목은 "URS 근거 없음, 기본값"으로 표기한다. 다른 파일은 만들지도 수정하지도 않는다.

완료 시 생성 파일과 커버한 URS 조항 ID, 구현 또는 분석하지 못한 조항 ID와 사유를 영어로 보고하라.
공유 파일 변경이 필요하면 수정하지 말고 요청 사항만 보고하라. 질문하지 말고 기본값으로 진행하라.
